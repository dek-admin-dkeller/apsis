How it finds what is close to what

The obvious way is to measure every object against every other one. The grid gets the same answer with a fraction of the work. Switch between them and watch the count.

Space is cut into squares as wide as the alert distance, and each dot is filed under its square in a hash table. Two dots that close must be in the same square or in squares that touch, so each dot is measured only against those. The pairs found are the same either way.

Positions come from public orbit data and a standard model, SGP4, run for the whole catalogue several times a second in the background. To look hours ahead, the same grid is used with wider cells and each candidate is then checked with the full model.

Public orbit data is good to about a kilometre. Apsis shows where to look and how the search is done. It does not say whether two objects will collide.

                  What you are looking at
                  
            
                  Every dot is a real object in orbit: an active satellite, a space station, or a fragment from a collision. Apsis places each one from published orbital data, moves it with the same physics model operators use, and — when the monitor is on — checks about once a second which objects are dangerously close to each other.
                  
            
                  That last step is the hard one. This page explains how it is done fast enough to run live in a browser, and shows the real numbers from the session you have open.

                  From data to dots
                  
            
                    
              
                  1. Orbital elementsCelesTrak publishes six numbers per object that describe its orbit, plus a drag term and the time they were measured. They are saved with the app, so it runs offline.
                    2. 
              
                  2. SGP4 propagationA background worker turns those numbers into an x, y, z position for any instant — for every object, three times a second — so the interface never stalls.
                    3. 
              
                  3. ScreeningThe same worker hashes every position into a grid and reports the pairs closer than the alert distance.
                    4. 
              
                  4. DrawingAll objects are one draw call. The graphics card glides each dot between two computed positions, which keeps motion smooth at 60 frames a second.
                    5. 
            
                  
          
                  

          
                  
            
                  The screening problem
                  
            
                  To find every pair closer than a distance d, the obvious method measures every pair. With n objects that is n(n − 1) / 2 measurements: double the objects and the work quadruples.
                  
            
                  
            
                  Almost all of that work is wasted. Two objects on opposite sides of the planet cannot be 10 km apart, and no measurement is needed to know it.
                  
          
                  

          
                  
            
                  The spatial hash
                  
            
                  Cut space into cubes exactly d wide. If two objects are closer than d, they are less than one cube apart along every axis, so they sit in the same cube or in two touching cubes. Around any cube there are only 3 × 3 × 3 = 27 of those.
                  
            
            
                  So the method is: put every object into the cube it is in, then for each object look only inside its own cube and the 26 around it. The cubes are kept in a hash table — a Map whose key identifies a cube and whose value is the list of objects inside it — so finding a cube takes the same short time whether there are a hundred objects or a million.
                  
            
          
                  

          
                  
            
                  The hash function
                  
            
                  A hash table needs one key per cube. Apsis builds it from the position in three small steps:
                  
            
                    
              
                  1. ix = floor(x / d)Which cube along x. The same for y and z.
                    2. 
              
                  2. ix += 65,536Shift so the three numbers are never negative.
                    3. 
              
                  3. key = (ix · R + iy) · R + iz,  R = 131,072Pack them into one number, like three digits in base R. Different cubes always get different keys, and the result stays small enough to be an exact integer.
                    4. 
            
                  
            
                  A number is used rather than text such as "3,-2,7" because building and hashing a string for each of the 28 lookups per object is four to five times slower — measured by the benchmark script.

                  Queryn(n − 1)/2 → O(n²)27 lookups per object + one check per candidate → O(n + k)
                  
                
                  Worst caseO(n²)O(n²) if everything lands in one cube

                  Looking ahead
                  
            
                  The monitor's Coming hours tab predicts close passes up to a day ahead. Asking "who is close?" once a minute would miss nearly everything: two satellites closing at 15 km a second are within a kilometre of each other for a fraction of a second.
                  
            
                  So the same hash is used with a wider net and a little geometry:
                  
            
                    
              
                  1. cell = alert distance + fastest closing speed × 30 sEvery simulated minute, hash everything into cells about 490 km wide. Any pair that will pass close during that minute is no further apart than this at the sample, so the 27-cell search is guaranteed to offer it up.
                    2. 
              
                  2. t* = −(r · v) / |v|²For each candidate pair, treat their relative motion as a straight line for those 60 seconds and solve for the moment of closest approach. Keep the pair only if that moment falls inside this minute and the straight-line miss is small.
                    3. 
              
                  3. refine with SGP4The few survivors get an exact search for the true closest point.
                    4. 
            
                  
            
                  One hour for every object takes about four seconds: roughly 40 million candidate pairs examined instead of 11 billion pair-checks. The benchmark script confirms it finds every crossing pair that brute-force sampling finds.
                  
          
                  

          
                  
            
                  Benchmark
                  
            
                  Both methods are run on the same positions at growing sizes. The benchmark times each one and confirms they return exactly the same list of pairs.

                  Limits
                  
            
                    
              
                  • Positions are predictions. They come from a model, accurate to about a kilometre when the elements are fresh and worse as they age.
                    • 
              
                  • One instant at a time. The monitor checks where everything is now. Real operators also search days ahead and compute a collision probability.
                    • 
              
                  • Many close pairs are intentional — docked spacecraft, satellites flying in formation, neighbours in the geostationary ring.
                    • 
              
                  • Cube size equals the alert distance. A very large distance puts many objects in each cube and the method drifts back towards measuring every pair.

                  About Apsis
                  
        
                  
          
                  Apsis shows every tracked object in Earth orbit and screens them for close approaches in real time. It began as a university algorithms project about hashing; the  page explains the method.
                  
          
                  Every 3D model in one place, to turn and look at: the .
                  
          
                  For learning and curiosity only. Positions are predictions from public orbital data, good to roughly a kilometre. Do not use Apsis for operational decisions.
